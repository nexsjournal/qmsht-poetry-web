# 《清明 · 虹桥》功能文档：过桥行人

虹桥之上出现行人：从桥的一端慢慢显形、沿桥面来回走过、走到对岸后渐渐消失，循环往复。行人作为背景点缀，不喧宾夺主，也不干扰诗帘与钟声交互。

## 1. 效果定义

单个行人的完整生命周期（状态机）：

```
等待(屏外, 不可见)
  → 上桥: 脚已踏上桥端后, 透明度 0→1 缓慢淡入（约 1~1.5s）
  → 过桥: 沿桥面弧线匀速行走, 身体朝向行进方向, 步态循环
  → 下桥: 临近对岸时透明度 1→0 淡出（约 0.8~1s）, 出桥边缘时完全消失
  → 销毁 → 随机延迟 1~4s → 重新生成（换方向/换人）
```

- 「上桥后再慢慢显示出来」：淡入起点在桥端内侧（人已踏上桥面 5%~8% 处），避免人在桥头凭空弹出。
- 「过桥后就消失」：淡出在到达对岸前开始、出桥边缘时完成，人离开画面后实体移除。
- 「来回走动」：行人分左右向两群（左→右 / 右→左），同一座桥上双向穿插；每个行人走完全程后消失，而非往返折返。

## 2. 现状与可行性

- 虹桥目前是**静态 PNG**（`assets/hongqiao-web.png` 1200×372，场景内 680×211），非 3D 模型。
- 因此行人用 **2D 精灵图 + 桥面弧线路径** 实现即可：不需要 3D、不需要物理引擎，DOM 层（或独立 canvas 层）+ rAF 驱动即可，性能开销可忽略。
- 可复用现有基础：`SCENE_W=720` 场景坐标系、`.scene` 的 `scale(var(--s))` 自适应、`reduceMotion` 开关、`dpr` 处理、「展画卷」模式钩子（`setPainting`）。

### 2.1 步行路径（已从 hongqiao-web.png 实测）

桥顶栏杆为弧线，行人脚底沿线行走（栏杆底部即桥面行走线）：

| 点 | 图内坐标 (1200×372) | 场景坐标 (680×211, ×0.567) |
| --- | --- | --- |
| 左端 | (60, 165) | (34, 93) |
| 拱顶 | (600, 42) | (340, 24) |
| 右端 | (1140, 165) | (646, 93) |

路径参数化（t∈[0,1]，相对 `.bridge` 容器）：

```
x(t) = 34 + 612t
y(t) = 24 + 70·(2t−1)²
```

实现时以这三点为初值，浏览器里微调至脚底贴合桥面（允许 ±3px 误差，行人小，肉眼不敏感）。行人层锚在 `.scene`（`.bridge` 左边 = 场景 x=20），故落地公式为 `x(t) = 54 + 612t`（已实现，`js/pedestrians.js`）。

### 3.3 实现要点

- **渲染层**：DOM `<img>` 层（方案一，推荐）——`transform`/`opacity` 走合成器，零 canvas 重绘成本；与诗帘 canvas 互不影响。备选：并入诗帘同一 canvas 会受其 z-index 2（桥图之下）限制，不选。
- **遮挡取舍**：默认行人图层 z-index 高于桥图（人整体可见，前侧栏杆不挡腿）。对小人点缀观感足够。
  - 可选精修（二期）：把 `hongqiao-web.png` 切成「后层（桥身+远侧栏杆）」与「前层（近侧栏杆+桥面）」两张透明 PNG，行人夹在两层之间（z-index 2.5），栏杆自然遮挡腿部，更接近真实过桥。需一次资产裁切，收益中等，默认不做。
- **状态机**（每个行人一个对象，对象池复用，上限 N 个）：

  ```
  { state: "waiting" | "enter" | "walk" | "exit",
    dir: +1 | -1, t: 0..1, speed, opacity, img, delay }
  ```

  - `enter`：t 从 0 起步（脚先踏上桥），opacity 在 t∈[0.05, 0.15] 区间 0→1（缓动）。
  - `walk`：t 按 `speed·dt` 推进；过桥时长 8~14s/人（随机），speed 由方向与随机系数决定。
  - `exit`：t∈[0.85, 0.98] 区间 opacity 1→0，t≥0.98 时销毁。
  - `waiting`：随机 1~4s 后重生（随机方向、随机人物图、随机微缩放 0.9~1.05）。
- **朝向与步态**：`scaleX(dir)` 翻转；单帧静态图叠加 ±0.5px、约 2Hz 的上下 bob 模拟迈步；多帧素材则每 ~150ms 换帧。
- **深度感（可选）**：`scale` 随 t 微变（两端 0.92 → 中段 1.0），强化拱桥透视。
- **模式联动**：
  - 「展画卷」模式（`body[data-mode=painting]`）：行人整体淡出并停止 rAF 更新，「回诗帘」恢复（不重置已有行人的 t，避免跳变）。
  - `prefers-reduced-motion`：不生成行人（或拱顶站 1 个静态人、不淡入淡出），与现有 `reduceMotion` 行为一致。
- **参数**（进 `CONFIG`，默认值）：`pedCount: 3`（同屏上限）、`pedDuration: 10`（过桥时长基准 s）、`pedFadeIn: 1.2`、`pedFadeOut: 0.9`、`pedGapMin/Max: 1/4`（重生间隔 s）。是否暴露到右上面板留待二期，默认只放 `CONFIG`。

## 4. 验收标准

| # | 标准 |
| --- | --- |
| 1 | 行人自桥端踏上后 1~1.5s 内淡入可见；桥端之外不可见、无弹出感 |
| 2 | 沿桥面弧线行走（脚底贴合桥面，拱顶最高、两端最低），无滑步/离地感 |
| 3 | 到达对岸边缘时完全淡出消失；画面外无任何残留元素 |
| 4 | 双向行人共存，方向与朝向一致，循环生成不重样（2~4 人轮换） |
| 5 | 不影响诗帘物理、钟声触发、滚轮展卷、面板交互（`pointer-events:none` 验证） |
| 6 | 「展画卷/回诗帘」切换时行人正确隐藏/恢复且无跳变 |
| 7 | `prefers-reduced-motion` 下无行人动画 |
| 8 | 小屏（`--s<1`）下随场景等比缩放，行人不错位 |
| 9 | 3 人同屏时帧率无明显下降（DOM transform 路径，目标 ≥55fps 中端设备） |

## 5. 实施步骤

1. **素材**：从原卷截取/描摹 2~4 个透明 PNG 行人，Pillow 脚本统一脚底与高度 → `assets/pedestrians/`。
2. **路径校准**：在 `.scene` 临时叠加参考点，微调 §2.1 三点坐标。
3. **`js/pedestrians.js`**：状态机 + 路径 + 淡入淡出 + 对象池；先在控制台手动驱动单人验证。
4. **接线**：`index.html` 图层、`style.css` 样式、`main.js` 初始化与模式联动、`CONFIG` 参数。
5. **走查**：按 §4 验收表逐项过；移动端与 reduced-motion 各验一轮。
6. **可选二期**：面板参数暴露、桥图前后两层拆分遮挡、4 帧步态循环、行人脚下淡影。
